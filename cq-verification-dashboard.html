How the system checks itself

These ran on all 12 packages, not a sample. None of them need a reviewer or a known answer — the system is checked against the document and against itself.

Every finding traces back to the page
The quoted text must actually appear where the system says it does. Anything it can't point to is held, not reported.
99.7%4 held
Numbers are recalculated, not judged
The reading and the acceptance limit are pulled out, then the pass/fail is computed in code. A disagreement means the reading was misread.
99.2%9 held
Same answer when asked again
Each check runs three times. If the answers differ, the item goes to a person instead of the system picking one.
97.8%26 held
A second reader agrees
An independent checker reviews the same page without seeing the first verdict. Disagreements go to review.
96.4%43 held
Nothing was skipped
Every rule returns an explicit answer and every page is read at least once. A silent gap is the failure that would otherwise go unnoticed.
100%2 pages unread
Rescanning doesn't change the verdict
The same package re-scanned or re-exported must produce identical findings. Catches sensitivity to scan quality and page layout.
99.1%11 held

Together these produced the 70 items sent back as uncertain — some tripped more than one check. When any of these fall, the system holds the item rather than clearing it, so a weak result costs reviewer time instead of letting a deficiency through.
